Homelab as Code

Until October, my home server was set up by hand, and the only record of how was the server itself.

Now every service is a folder in a git repo: its Compose file, its settings, and a README that says why.

An Ansible playbook turns a fresh Ubuntu install into the same server; I proved it on 30 October on a lab VM. GitHub Actions checks every push, and a dead man’s switch tells me when monitoring goes quiet.

How a change ships

Laptop, CI, a throwaway VM, then a dry run on the real server.

First, CI checks every push.

git push origin main

CI 6 of 6 jobs passed · longest 38s (ansible-lint)

Then, Ansible builds it on a throwaway VM.

ansible-playbook site.yml -K
PLAY RECAP · lab VM rebuilt from an empty disk, 30 Oct
testvm    changed=35   failed=0
same playbook, second run: nothing left to fix
testvm    changed=0    failed=0

Only then does the real server get a dry run first: --check --diff.

Finally, if the server goes quiet, I hear about it.

docker compose stop   # test B: silence the dead man's switch

Things I’ve built

Homelab as Code

Docker · Ansible · CI

My home server, described in a git repo: each service as a Compose stack, an Ansible playbook that rebuilds it from an empty disk, CI on every push, and Prometheus and Grafana watching it. The repo is private; I’m happy to walk you through it.

claude-ops

Linux · systemd · nftables

An AI assistant that writes a read-only daily health report for the server and answers questions in Discord, built so it can look but not touch. It runs as its own user with no sudo and no Docker, an nftables rule lets it reach only the AI provider’s API, and the Discord token stays with a separate relay that has no AI.

SENSE-LoRa

ESP32 · LoRa · thesis

Our BS Computer Engineering thesis at PUP, defended in October 2026: an ESP32 seismic detection unit and three Heltec LoRa nodes that sound earthquake sirens in under 700 ms, and let focal persons message each other with no internet.

About me

Hi, I’m Edmharx. I study Computer Engineering at the Polytechnic University of the Philippines in Sta. Mesa, and I work as an IT desktop support intern at TradeWindow.

I want to work in DevOps, and I’m learning it on a server I depend on. My home server used to be set up by hand, and the only record of it was the machine itself. Now it is a git repo that can rebuild it.

Every change takes the same path: written on my laptop, checked by CI, tried on a throwaway VM, and dry-run against the real server before it touches it. When something breaks, the history says what I tried and why.

Our thesis, SENSE-LoRa, taught me the other half: systems that have to keep working when the internet doesn’t. I’m looking for a place to keep learning this on real infrastructure.
